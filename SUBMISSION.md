## Problem statement chosen

**PS04: Persona Design.** Today VANI talks to every seller in one voice and one style for the whole call. We build a persona that fits each seller **before the call**, from that seller's data, and **adapt it live** when the seller gets frustrated, confused, rushed or interested, or switches language.

## Approach note

1. **Seller data in.**
   - All the PS07 files are ingested into an indexed SQLite database: 149,363 sellers, 336,606 bot and executive calls, and 139,545 transcript turns.
   - The seller file has no business-name column, so names are recovered from call summaries. Lookup is by GLID or by name, with 404 suggestions and 409 for names shared by several sellers.
2. **Evidence from past calls.**
   - The 269k bot calls are mined for which choices go with meetings being fixed: pace, opening, behaviour after each signal, language by region, and objections.
   - Each finding carries its sample size and a strength label.
3. **Persona generator, one per seller** (`POST /api/v1/supplier/persona`).
   - It sets the voice (gender, accent, pitch, pace), the language (opening and switch language, Hinglish mix, formality) and the tone (warmth, empathy, assertiveness).
   - It builds a conversation plan: opening, personalisation, objection playbook, escalation rules and guardrails.
   - **Every choice has a reason, the data fields it used, past-call evidence and a confidence.** Missing fields lower the confidence.
   - It also suggests an IndiaMART package by turnover, with listed prices only.
4. **Into the call.**
   - Before the first word, the Sarvam agent calls `fetch_seller_persona` and receives 18 per-seller variables.
   - The prompt (`sarvam/agent_prompt.md`) holds what is the same for every seller: facts, hard stops and guardrails. The variables carry the per-seller persona.
5. **Live adaptation.**
   - VANI detects frustration, confusion, rush, interest and a language switch, plus bot questions and opt-outs.
   - It changes delivery only, never facts or prices (FAQ Q5).
   - It calls `log_persona_switch` with the signal, the change, the reason and the seller's words, which builds the **switch log**.
6. **After the call.** `send_call_outcome` stores the outcome, the meeting or callback time, the objections and a summary against the same `call_ref`. `GET /api/v1/calls/{call_ref}` shows one call end to end.
7. **Safety.**
   - A pre-dial do-not-call filter, plus stop variables during the call.
   - A cautious permission-first path for sellers we can't look up.
   - Truthful about being automated if asked; never claims to be human.
   - Numbers are spoken in words generated by code.
   - A token-protected API.
8. **LLM.**
   - The optional LLM (OpenAI `gpt-4.1-mini` or Anthropic `claude-haiku-5-5`, structured output) adds a narrative layer.
   - It is **switched off in this submission** (`LLM_ENABLED=false`, no key), so all personas come from the deterministic, evidence-backed rule engine. Sarvam's own LLM runs the live conversation.

## How to review the code quickly

```powershell
pip install -r requirements.txt
python -m pytest -q                  # 106 tests, no keys, no data needed
```

To run it on the real PS07 data, copy the CSVs into `data/` and run `python -m scripts.ingest` (about 75 s). See `README.md`.

**Not included in the zip:**
- **The raw seller CSVs and the 560 MB database.** They contain real seller data and can be rebuilt with the ingest script.
- **`.env`.** It holds the API keys; `.env.example` lists the settings.
